⏺ Good question. Given EGDesk is a local-first platform for small businesses
  with SQLite backing, here are features that would pair well with pub/sub:

  High value:

  1. Job Queue — enqueueJob('send-receipt', { orderId }), with status tracking,
  retries, delayed execution. Backed by a _jobs table. Very natural next step
  from pub/sub — "react to events" vs "schedule work."
  2. Audit Log / Change History — automatic row versioning. Every
  insert/update/delete gets logged with before/after snapshots. Korean
  businesses need this for compliance. Could expose getRowHistory(table, rowId).
  3. Webhooks (outbound) — like pub/sub but pushes to external URLs. User
  registers onDataChanged → POST https://my-slack-webhook. Complements SSE
  (inbound to browser) with outbound to any service.

  Medium value:

  4. Scheduled Queries / Cron — scheduleQuery('daily-summary', '0 9 * * *', 
  'SELECT ...'). Useful for reports, cleanup, recurring tasks.
  5. Materialized Aggregations — auto-maintained rollups like "total orders by
  status" that update on every write. Faster dashboards without manual
  re-querying.
  6. Row-level Locks / Optimistic Concurrency — updateRow(..., { 
  expectedVersion: 3 }). Prevents conflicts when multiple tabs/users edit the
  same row.

  Nice-to-have:

  7. Data Expiry / TTL — auto-delete rows after N days (session tokens, temp
  data)
  8. Blob/File Attachments — attach files to rows with a storage API

  ---
  My take: Queue is the strongest next feature. It's the natural companion to
  pub/sub — pub/sub says "something happened," queue says "do something about
  it." Together they form an event-driven system that's really compelling for a
  demo. You could show: insert order → SSE notification appears on phone → job
  auto-enqueued → job processes (e.g. "generate invoice") → another SSE
  notification shows "invoice ready."

  Want me to spec out the queue?
